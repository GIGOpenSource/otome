# 部署

先在项目根目录准备环境变量和证书，再构建镜像。

## 1. 环境变量

```bash
cp .env.example .env
```

`.env` 里至少要改这些值：

- `POSTGRES_PASSWORD`（`POSTGRES_HOST` 默认 `postgres`，走 compose 内网）
- `REDIS_PASSWORD`（不能为空）
- `OTOME_ADMIN_PASSWORD`
- `OTOME_FRONTEND_BASE`：玩家打开网站时使用的地址，例如 `https://example.com`
- `STORAGE_BACKEND`：`1`=GCS、`2`=COS（默认）、`3`=MinIO；按所选后端填写 `COS_*` 或 `GCS_*` 或 `MINIO_*`
- `DJANGO_SECRET_KEY`、`OTOME_TOKEN_KEY`

`OTOME_TOKEN_KEY` 必须正好是 16、24 或 32 个字符（例如 `0123456789abcdef`）。素材上传后直接走对象存储公开 URL。改了 `nginx.conf` 需要重新构建 nginx 镜像。

## 2. 页面和证书

Nginx 只读取已经打包好的目录，不在容器里编译前端。

- 玩家页放到 `page/frontend`，后台放到 `page/admin`（三个域名共用）
- SSL 证书放到 `page/cert/`（与 Trandsai 相同布局）：
  - `jnacaoxi_live.crt` / `jnacaoxi_live.key` → `caoxi.live`
  - `jnaruxi_ink.crt` / `jnaruxi_ink.key` → `ruxi.ink`
  - `jnacaoxi_life.crt` / `jnacaoxi_life.key` → `caoxi.life`

打包前端（输出拷到 `page/`）：

```bash
# 玩家 H5 → page/frontend
cd frontend/game-client
npm install
npm run build:h5
# 将 dist/build/h5 内容拷到 ../../page/frontend

# 后台 → page/admin（.env.production 已设 VITE_BASE=/admin/）
cd ../admin
npm install
npm run build
# 将 dist 内容拷到 ../../page/admin
```

H5 接口地址为同域 `/api`，访问 `caoxi.live` / `ruxi.ink` / `caoxi.life` 均可；App 默认 `https://caoxi.live/api`。

## 3. 启动

```bash
docker build -f Dockerfile.base -t otome-base:v1 .
docker compose up --build -d
```

容器启动时会执行数据库迁移。PostgreSQL 和 Redis 都在 compose 里：库数据在卷 `otome_postgres`，Redis 在 `otome_redis`；Postgres 只映射 `127.0.0.1:5432`，不对公网开放。停止时不要使用 `docker compose down -v`，否则库和登录状态都会被清掉。

改了 `nginx.conf` 需要重新构建 nginx 镜像。只换 `page/frontend` 或 `page/admin` 里的文件时，执行 `docker compose up -d` 即可。
