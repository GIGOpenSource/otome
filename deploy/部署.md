# 部署

先在项目根目录准备环境变量和证书，再构建镜像。

## 1. 环境变量

```bash
cp .env.example .env
```

`.env` 里至少要改这些值：

- `POSTGRES_HOST`、`POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD`
- `REDIS_PASSWORD`
- `OTOME_ADMIN_PASSWORD`
- `OTOME_FRONTEND_BASE`：玩家打开网站时使用的地址，例如 `https://example.com`
- `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`
- `DJANGO_SECRET_KEY`、`OTOME_TOKEN_KEY`

`OTOME_TOKEN_KEY` 必须是 16、24 或 32 字节。

## 2. 页面和证书

Nginx 只读取已经打包好的目录，不在容器里编译前端。

- 玩家页放到 `page/frontend`
- 后台页放到 `page/admin`
- 证书放到 `ssl/fullchain.pem` 和 `ssl/privkey.pem`

`nginx.conf` 里的域名、证书文件名，以及 `/storage/` 转发到的对象存储地址，要改成和 `.env` 一致。对象存储自己返回的跨域头会被 Nginx 去掉，只保留一份 `Access-Control-Allow-Origin`。

## 3. 启动

```bash
docker build -f Dockerfile.base -t otome-base:v1 .
docker compose up --build -d
```

容器启动时会执行数据库迁移。库是外部 PostgreSQL，不在这个 compose 里。Redis 的数据写在数据卷 `otome_redis` 中。停止时不要使用 `docker compose down -v`，否则登录状态会被清掉。

改了 `nginx.conf` 需要重新构建 nginx 镜像。只换 `page/frontend` 或 `page/admin` 里的文件时，执行 `docker compose up -d` 即可。
